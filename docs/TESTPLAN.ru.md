# Матрица ошибок и проверка платформенной упаковки

<!-- ai-generated: verification model for Debian, Keenetic, releases and updates. -->

Документ разделяет автоматические проверки, теоретически разобранные отказы и проверки, которым нужен реальный VPS, Keenetic и внешний WebRTC provider. Отсутствие стендового теста не обозначается как успешный результат.

## Что проверяется автоматически

### Исходный код

- `go test -race -count=1 -short ./...` в Linux CI;
- `mage check` перед релизом, включая format, build, vet, lint и полный быстрый набор тестов;
- сборка `linux/amd64` и `linux/arm64` из одного checkout;
- проверка, что записанный официальный upstream commit является предком release HEAD.

### Shell и Python

- ShellCheck в режиме POSIX `sh`, включая обе Entware init-службы;
- синтаксическая проверка shell-файлов;
- unit-тесты строгого manifest parser, Spec URI importer, парольной схемы, bind policy и redaction веб-панели;
- запуск release assembler в `dash` и BusyBox `ash`;
- проверка GitHub Actions через обязательные CI jobs после публикации.

### Release

- manifest содержит ровно девять scalar и четыре asset row;
- разрешены только `core|bundle`, `linux`, `amd64|arm64` и известные wire/schema;
- отсутствуют дубли архитектурных asset;
- имена asset являются безопасными basename;
- размер положительный, SHA-256 содержит 64 lowercase hex;
- оба core и оба bundle связаны с одним `source_commit`;
- `latest` повторно разрешается в точный tag до установки.

## Keenetic: ожидаемые отказы

| Этап | Отказ | Ожидаемое поведение |
|---|---|---|
| Предварительная проверка | Не root, нет `/opt`, нет `opkg`, не ARM64 | Остановка до изменения файлов |
| Зависимости | DNS, TLS, неверное время, нет места | Понятная ошибка `opkg` или download, старый клиент не останавливается |
| Manifest | Лишнее поле, дубль, другой repository, неверный wire/schema | Отклонение без выполнения содержимого manifest |
| Bundle | Неверный размер/SHA, symlink, absolute path, `..`, более 100 entries | Отклонение до запуска `install.sh` |
| Spec URI | Markdown, ключ не 64 hex, `jitsi room=any`, URL без комнаты | Старый конфиг и ключ остаются активными |
| Совместимость | `wbstream + datachannel`, удалённый Telemost datachannel | Отклонение при импорте URI |
| Первый запуск | Дочерний процесс сразу падает | Пять ограниченных повторов, затем состояние `blocked` |
| Обновление | Новый бинарник не создаёт SOCKS за 30 секунд | Восстановление бинарника, release metadata и manifest URL |
| Обновление | `--no-start` | Установка проверенного файла без повторного запуска клиента |
| Web | Wildcard bind, короткий пароль, неверный Origin/CSRF, серия логинов | Отклонение запроса; WAN не настраивается |
| Миграция | Старая служба держит `8808`, новый клиент не запускается | Старый init сохраняется, при неудаче запускается обратно |
| Удаление | Обычный режим | Конфиг и state сохраняются |
| Удаление | `--purge` | Удаляются только фиксированные пути пакета |

Проверка rollback должна дополнительно убедиться, что PID supervisor не принимается за PID дочернего olcRTC и что один живой supervisor без SOCKS не считается успешным запуском.

## Debian: ожидаемые отказы

| Этап | Отказ | Ожидаемое поведение |
|---|---|---|
| Платформа | Не Debian 12 или не `amd64` | Остановка до установки release |
| Конфиг | Placeholder, `room.id=any`, не `mode: srv` | Unit не запускается |
| Bundle | Неизвестный путь, symlink или отсутствующий обязательный файл | Распаковка отклоняется |
| Бинарник | Не запускается или не показывает ожидаемый CLI usage | Release не активируется |
| Обновление | Один из активных unit не стартует | Атомарная ссылка и systemd unit возвращаются к предыдущим |
| Удаление | Без `--purge` | YAML, ключи и state сохраняются |
| Namespace | Установлен старый Manager или fork v0.1.1 | Новые unit и каталоги не заменяют старые; перенос только по явному подтверждению |
| Admin Web | Неверный пароль, CSRF, опасный instance, `room=any`, несовместимая пара | Отклонение до записи YAML или выполнения systemctl |

## Проверки на реальном стенде перед стабильным релизом

1. Установить один и тот же prerelease tag на чистый Debian 12 VPS и Keenetic Entware ARM64.
2. Проверить `jitsi + datachannel`: handshake, DNS через SOCKS, HTTP и длительную передачу.
3. Проверить `wbstream + vp8channel` отдельно, не смешивая URI от другого release.
4. Оборвать питание Keenetic во время загрузки, после записи bundle и после замены бинарника. После загрузки должен остаться либо старый, либо полностью установленный новый release.
5. Заблокировать provider, DNS и GitHub по очереди. Управление LAN и обычный интернет роутера не должны пропасть.
6. Подменить manifest, один байт core и tar entry с traversal. Каждый вариант должен быть отклонён.
7. Выполнить обновление на намеренно завершающийся бинарник и подтвердить возврат старого SOCKS.
8. Проверить перезагрузку роутера, ротацию логов, повторную установку, удаление и `--purge`.
9. Проверить веб-панель с неверным паролем, истёкшей сессией, CSRF, чужим Origin и прямым WAN-доступом.
10. Только после этого снять prerelease и опубликовать стабильный tag.

Автоматическое включение TUN и маршрутов LAN в эту матрицу не входит, потому что первая версия их не устанавливает. Для такого режима нужен отдельный дизайн с аварийным bypass, сохранением доступа к Keenetic и независимым rollback маршрутов.
